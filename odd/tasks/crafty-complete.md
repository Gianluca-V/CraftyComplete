# craftyComplete — mod and modpack companion for Crafty Controller 4

Objective: standalone, open-source Python + FastAPI service that adds Modrinth mod/modpack browsing, install, update and server creation on top of the Crafty Controller 4 API v2.
Branch: `feat/base-modrinth-search` · Delivery: `ask-on-risk` · Test runner: `pytest` (`.venv/Scripts/python -m pytest`).

## Specs

- **S1 — Search view.** "Poder buscar mods y modpacks con una vista similar a CourseForge o Modrinth". Source: Modrinth first ("No tengo una api de CourseForge, empecemos con modrinth si es mas sencillo"); keep a provider abstraction so CurseForge can be added later.
- **S2 — Add mods to servers.** "los mods deben poder agregarse a servidores". Required dependencies install automatically and client-only mods are rejected ("idealmente quiero que se instalen as dependencias requeridas automaticamente y que se validen los mods para que no pasen mods de solo cliente"). Mods that cannot be downloaded automatically: "saltearlos y avisar para subirlos a mano".
- **S3 — Create servers from a modpack.** "se deben poder crear servidores directamente desde un modpack (incluidos los que requieren ejecutar un archivo bash para auto construirse)". Example: "Al descargar el server pack de prominence II se necesita ejecutar un archivo bash que construye los archivos de servidor completos." All loaders: "se necesitan soportar todos los loaders". Narrowed for now (L23): "vamos con opcion a por simplicidad, no es necesario por ahora soporte para Quilt, solo Forge, NeoForge y Fabric" — the loader is installed by Crafty's own installer (newest loader build Crafty offers for the pack's Minecraft version), with a warning when it differs from the version the pack names.
- **S4 — Updates.** "actualizar facilmente con un boton mods especificos y modpacks completos dentro de un servidor". "manuales con boton y con chequeo automatico, que no se actualizen solos, unicamente deben tener un indicador de actualizacion disponible, tambien debe haber un boton de actualizar todos los mods." Modpack update: "que funcione como lo hace CourseForge" (proposed: replace pack mods, keep user-added mods, automatic Crafty backup first — to confirm).
- **S5 — Adopt existing servers.** "quiero que pueda adoptar servidores": hash `mods/*.jar`, identify on Modrinth, states identified / unknown / pinned, optional link to a modpack.
- **S6 — Permissions and integration.** "usemos los permisos de crafty". Separate app: "me sirve una app aparte pero estaria bien que se vea al menos un link desde crafty". Deployment: "crafty fue instalado en un proxmox usando los VE Scripts" (Linux LXC; the companion must reach the Crafty server directories).
- **S8 — Modpack updates on existing servers.** "quiero poder entrar a un servidor que ya tengo, ver si hay alguna version nueva del modpack que usa (Prominence II), actualizarlo con los mods y configs correctas y agregarle contenido a ese modpack como Distant Horizons." Behaviour as agreed earlier (S4): "que funcione como lo hace CourseForge" — replace the pack's files, keep what the user added.
- **S7 — Base.** Configuration via environment, Crafty API v2 client authenticated with an API token, health endpoint reporting Crafty connectivity. No Crafty data is exposed until S6 authentication exists.
- **S9 — Server status and power.** "iniciar o detener servidores", "ver el estado de cada servidor (prendo o apagado, cantidad de jugadores online, uso de ram y cpu, etc)". In the web UI and the MCP (L38).
- **S10 — Remove mods and pick a version.** "agregar o eliminar mods de un servidor, actualizarlos o seleccionar una version", "que al agregar un mod se agreguen automaticamente sus dependencias". Removing a mod (L38): if another mod requires it, it is blocked unless confirmed; dependencies left unused (installed automatically) are listed and removed only when confirmed. Picking a version (L38): only versions compatible with the server's Minecraft version and loader; a chosen version is not pinned, so the next "Update all" can move it to the newest.
- **S11 — Player management.** "gestionar los usuarios" means Minecraft players (L38): whitelist, op, ban and kick. Running server: console commands through Crafty. Stopped server: edit `whitelist.json`, `ops.json` and `banned-players.json`, resolving the UUID through Mojang. Kick only while running.
- **S12 — Create vanilla and modded servers.** "necesitamos poder crear servidores vanilla o con mods o con modpacks". Vanilla (L38): official Mojang server and Paper, choosing the Minecraft version; plugin management is out of scope. With mods (L38): choose Minecraft version and loader (Fabric, Forge, NeoForge) and optionally a list of Modrinth mods, installed with their required dependencies; the server ends up adopted.
- **S13 — MCP.** "crear un MCP para poder controlar todo desde un agente de IA". Local stdio server launched by the MCP client, authenticated with a Crafty API token from an environment variable, so Crafty enforces that user's permissions (L38). Destructive actions (removing mods, stopping servers, banning, changing a modpack version) take two steps: the tool returns a plan and a token, and a second call with that token executes it (L38). Covers existing and new features.
- **S14 — Surfaces.** New features are available in the web UI and as MCP tools, sharing the same application logic (L38).
